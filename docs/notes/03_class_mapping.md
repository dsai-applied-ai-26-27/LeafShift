# Class mapping - 9-class definition with evidence

**Status: FINAL. The team decided on 9 classes on 2026-11-15, and the PlantDoc review is complete.**

All counts were generated by `notebooks/01_data_exploration_and_quality.ipynb` on 2026-11-15 from the exact dataset copies in `data/raw/`. Machine-readable source: `data/processed/week7_class_mapping_counts.csv`, `data/processed/class_mapping_check.csv` and `data/processed/plantdoc_review.csv`.

## Decision: 9 classes, not 10

The original proposal named 10 classes. PlantDoc has **no healthy potato folder at all**, under any spelling. A 10-class model could therefore only be scored on 9 of its classes in the field, and macro-F1 is only comparable between the two sides when both score the same label set.

Decision: **drop Potato - healthy from the shared label space.** The model has 9 classes everywhere, and every class it predicts can be scored on PlantDoc.

Potato - healthy is not deleted from disk. It stays in `data/raw/` as 152 images and is simply outside the experiment's scope, exactly like the bell pepper, mosaic virus, yellow leaf curl and target spot folders.

Every decision carries `reviewer = Emin Hadziabdic` and `review_date = 2026-11-15`. Every `remove` carries a written reason, which is what the Week 3 feedback asked for ("document who made each decision").

The 4 removals are 3 images in `Tomato_leaf_bacterial_spot` and 1 in `Tomato_mold_leaf`. They are removed from the evaluation only; the files stay on disk.

## Remaining gap: Tomato - spider mites has 2 PlantDoc images

The mapped folder holds 2 images in `train` and 0 in `test`. A 2-image class cannot support a per-class F1 estimate and will make macro-F1 unstable.

Decision: declare it **unevaluable on PlantDoc** and say so in the report. Do not report an F1 computed from 2 images.

That leaves **8 classes with a usable PlantDoc sample**, holding **984** of the 986 kept images.

| train | 910 | 912 |
| test | 74 | 74 |

The official PlantDoc test split holds 252 images in total, but only 74 of the kept images belong to our evaluable classes. A macro-F1 computed on 74 images has a wide confidence interval, which is why the plan uses bootstrap intervals. Report the interval, never the point estimate alone.

## Duplicate check result (PlantVillage)

Method: SHA-256 for byte-identical files, then pHash (Hamming distance <= 4) for visually similar candidates. Both ran over all 20,638 images with 0 failures.

| Check | Pairs | Distinct files | Same class | Cross class | Recorded |
|---|---:|---:|---:|---:|---|
| Exact duplicates (SHA-256) | 14 | 28 | 14 | 0 | **yes, 14 exclusions** |
| Near-duplicate candidates (pHash) | 52 | 104 | 44 | 8 | candidates only |

**The 14 exact pairs are resolved.** All are same-class: 6 in `Tomato_healthy`, 8 in `Tomato_Late_blight`. One file from each pair was recorded in `plantvillage_exclusions.csv` with reviewer `Emin Hadziabdic` and review date `2026-11-15`. PlantVillage therefore holds **20,624 usable images** (20,638 minus 14), and the 9 selected classes hold 13,012.

**The 52 near-duplicate candidates are not resolved and must not be treated as duplicates.** 8 of them cross a class boundary, which suggests several are false positives from similar leaf shapes. Each needs a human look before anything is excluded.

## Better leakage control is available

The upstream PlantVillage repository publishes official leaf grouping metadata at `leaf_grouping/leaf-map.json` (Hugging Face mirror `mohanty/PlantVillage`), plus ready-made splits that respect that grouping.

A direct test on this copy mapped **14,935 of the 20,638 images (72.4%)** to an official leaf ID; the per-image result is `data/processed/plantvillage_leaf_map_coverage.csv`. Using those IDs to keep one physical leaf on one side of the split is stronger than pHash, which can only find what looks alike. The remaining 28% would fall back to pHash and the capture-session tags in the file names (`GH_HL`, `GHLB2`, `JR_B.Spot`, `GCREC_Bact.Sp`).

This is the recommended way to build the split. It is not yet implemented.

## Rule that still applies

Do not silently map two labels that are not equivalent. If a class is missing from one dataset, record the decision and the reason here. Do not fill a missing count with zero unless the class has been confirmed absent from the exact dataset copy.
